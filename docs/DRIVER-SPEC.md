# 应用与设备操作规范

规范版本：`1.0.0`；状态：`stable`；驱动结构版本：`2.0`；基线：ai-native-cli-spec `v1.6.3`。

本文供 CLI 实现者、适配器作者和验收人员使用，假设读者了解命令行、JSON 和所驱动工具的基本操作。
机器接口遵循[核心协议](CORE-SPEC.md)和基线 CLI-SPEC，验证证据遵循[验证规范](VERIFICATION-SPEC.md)。

## 目标与适用范围

本规范定义直接驱动应用或设备时，如何识别目标、控制修改范围、核实结果和处理失败。文件编辑、会话内操作和设备动作都可以声明为能力；实现只需支持它公开声明的能力。

本规范不替代应用自身的领域规则、设备操作规程或行业认证。接口合规不能证明设计正确，也不能证明设备适合某项任务。

术语约定：

| 术语 | 含义 |
|---|---|
| 实例 | 一个可识别的应用进程、服务端执行器或设备连接目标 |
| 会话 | 实例中的连接上下文，具有生命周期和连接身份 |
| 文档 | 应用内打开的工程、模型或其他可编辑对象集合 |
| 目标 | 命令实际观察或修改的实例、文档、文件、对象或设备状态 |
| 基线 | 一组已观测的目标状态及其观测时间、版本或指纹 |
| 任务范围 | 人授予的目标、允许的效果、可写位置、输出位置和期限，记录在范围文件中 |
| 检查点 | 为恢复或比较保存的一组状态与依赖，恢复范围必须明确 |

典型场景：在已打开文档中连续修改、在副本中试构建、批处理独立文件、执行有依赖的多步操作，以及查询或驱动设备。

## 能力与目标身份

### DRV-001 声明真实能力

实现必须在 reference 的 driver 块公开支持的阶段、模式、兼容环境、限制和恢复能力。原子性、撤销、幂等和取消在 `driver.recovery` 声明；试执行、设备模拟、连接方式和并发限制在 `driver.limits` 中逐项写明。这些能力不得由通用包装器推定。

验收：调用未支持的能力返回 `E_UNSUPPORTED`，且不触发替代操作；能力声明可以与实际行为逐项核对。

### DRV-002 明确选定实例

修改命令必须明确实例或唯一解析出的目标。存在多个候选实例时必须要求显式选择，不得依赖窗口焦点或最近使用顺序。新建或连接实例后必须返回其身份。

验收：同时打开两个候选实例时，省略选择不能修改任何一个；显式选择只作用于指定实例。

### DRV-003 处理身份生命周期

会话、文档及对象身份必须声明有效期或稳定性；运行实例模式还必须识别连接代际。重连后必须核对实例、文档和活动操作，不能因名称相同而沿用旧代际的引用。重连、关闭再打开、再生或替换对象后，失效身份必须拒绝使用或重新解析，并返回解析依据。

验收：重启实例、重连或重建对象后，旧身份不会误指向另一个对象；新的连接不会静默接管旧代际的操作。

### DRV-004 绑定文档和文件

具有文档或文件状态的模式必须区分文档身份与文件路径，记录文档是否新建、是否有保存位置。路径必须解析为明确位置；两个文档指向同一路径时，修改与保存不得静默选取其中一个。设备等没有文档或文件的模式必须标明这些维度不适用，并说明原因。

验收：按模式覆盖未保存文档、同名异路径文件和同路径多会话；没有文档或文件的模式报告不适用，不伪造目标。

### DRV-005 分别观测内存和磁盘

具有会话状态或磁盘状态的模式必须分别报告适用的维度，包括未保存修改、观测时间及版本或指纹。存在但无法读取的状态必须标为未知，不能用磁盘指纹代表内存版本。文件模式没有运行中会话、设备模式没有文件持久化等情形必须标明不适用并说明原因；持久化维度使用核心协议的 `not_applicable`。

验收：按模式验证内存修改与磁盘基线分离；不存在的状态维度报告不适用，存在但不可观测的部分报告未知。

### DRV-006 声明单位与坐标

具有量纲或空间含义的参数必须在 reference 中声明 `unit`；坐标系、原点和容差按参数语义声明。计数、标识符及索引不要求单位。默认值必须可发现；输入单位与应用单位不同时，必须按已声明的策略显式转换并记录，或拒绝不支持的组合，禁止猜测缺失的单位。

验收：相同物理量用不同的受支持单位输入，读回结果在声明容差内相等；不支持的单位不会静默降级。

### DRV-007 记录影响结果的依赖

执行前必须识别命令所需的库、模板、参考对象、插件和配置，并记录可取得的版本或指纹。缺失的依赖必须在可检测的最早阶段报告；无法固定的依赖必须披露。

验收：替换已识别的依赖后，结果证据能区分两次环境；缺失库不会生成伪成功的结果。

### DRV-008 显式管理实例生命周期

启动、连接、打开、关闭和重启必须声明作用范围。运行实例模式必须区分由工具启动并管理的实例（`owned`）与附着的已有实例（`attached`），并在 `context.environment.connection.ownership` 报告；所有权标记不能扩展任务授权。
CLI 退出、断开连接和关闭原应用必须分别声明策略，附着的实例不得因退出或断开而被隐式关闭。关闭或重启可能丢弃未保存修改时，必须核实任务授权并报告影响，不得把它隐藏在普通查询中。

验收：查询失败不会擅自重启实例；退出附着会话后，原应用和已有修改都还在；生命周期操作能说明哪些文档受影响、修改是否已保存。

## 任务范围与工作区

### DRV-009 记录任务授权

除 `observe` 外的效果都必须在任务范围之内。任务范围是一份符合 [scope Schema](../schemas/scope.schema.json) 的记录，内容是范围 ID、工具、授予人、授予时间、到期时间、允许的效果、是否允许危险命令、可写根目录、输出目录、交付位置、可选的目标选择和次数限制。

- 位置：环境变量 `<TOOL>_SCOPE_FILE` 指向的文件（TOOL 为工具名转大写、`-` 换成 `_`），否则是默认的 `~/.<tool>/scope.json`。
- 写入者：由人写，或由人明确指示 Agent 写；CLI 只读不写，不提供授权命令（基线 SEC-SPEC §3：Agent 不能自我提权）。
- 缺省：没有范围文件时 CLI 处于只读状态，只允许 `observe`。
- 路径：`roots`（可修改、保存的文件所在目录）和 `outputs`（新产物目录）必须是绝对路径，相对路径会随工作目录变化，按格式无效处理；`destinations` 是允许交付的位置前缀，允许 `deliver` 时必须列出。
- 前缀比较：交付位置和目标选择器的 `locator_prefix` 按 URL 的协议、主机和完整路径段比较，本地路径和 `file:` 定位符按解析后的真实路径比较；`share://release` 不覆盖 `share://release-evil/`。带用户信息、查询、片段或 `.`、`..` 段的位置一律不匹配，写在范围文件里则整份范围无效。指向网络共享的路径只有在根目录明确列出该共享时才会被解析。
- 次数：`limits.max_operations` 是这份范围下允许确认的操作次数，用完后按越界处理（DRV-010），`details.scope.missing.limit` 说明。
- 失效：到期、`revoked: true`、格式无效或工具名不符时，按缺省处理并在 context 中说明原因。
- 生效：每次 dry-run 和 confirm 都重新读取并核实；计划、令牌和回执记录所用的范围 ID。
- 展示：`context.authorization` 报告当前范围摘要，doctor 的 `authorization` 检查报告是否可用。

范围内的连续修改不要求每一步重新人工确认；`--dry-run` / `--confirm` 是 Agent 自己完成的计划绑定，不是人工批准。生成的计划、目标文档内容和 Skill 都不能扩大范围。

验收：同一范围内的连续修改可以自主执行；回执可关联到所用的范围；没有范围文件时，任何写命令的 dry-run 都返回 `E_FORBIDDEN`。

### DRV-010 在越界前停止

动作超出任务范围，或要求丢弃未授权的已有工作、改写共享目标、改变全局配置、向范围外交付时，必须在该动作开始前停止，返回 `E_FORBIDDEN`。`details.scope` 列出当前授权、缺少的效果、路径或目标，以及授权文件的位置和示例。已经存在的授权不得重复索取。

验收：在允许修改的副本中正常迭代；试图覆盖范围外的文件时，目标保持原状，错误指出具体缺少什么、由谁在哪里授予。

### DRV-011 明确隔离边界

工作区必须列出可写目标、输出目录和共享依赖。声称隔离时，必须说明隔离方法及未覆盖的副作用。目录副本不能证明应用配置、共享库或外部系统同样被隔离。

验收：试执行后的写入可以与声明的范围核对；对共享依赖的写入被禁止，或单独授权并如实记录。

### DRV-012 保留基线与已有工作

接手已有文档时，必须在首次修改前观测目标和未保存状态，并按恢复能力建立基线。无法建立完整基线时，必须声明可恢复的范围，不得承诺保留全部状态。

验收：已有修改不会被新基线静默丢弃；恢复说明区分磁盘文件、内存文档和未捕获的状态。

## 操作阶段与预览

### DRV-013 区分操作阶段

一条命令可能经过多个阶段。阶段与协议字段的对应关系固定如下：

| 阶段 | 协议中的表达 |
|---|---|
| 观察 | 只读命令，phase `observe`，效果 `observe` |
| 计划 | `--dry-run`，phase `plan`，返回计划 |
| 试执行 | `--dry-run` 的预览等级 `trial_observed`，只写隔离区 |
| 应用 | `--confirm`，phase `apply`（长任务为 `submit`），效果 `change` 等 |
| 保存 | 应用中的 `persist` 效果，回执的 persistence 维度 |
| 对外交付 | 应用中的 `deliver` 效果，回执的 delivery 维度 |
| 验证 | 回执的 verification；独立检查命令为 phase `verify` |

复合命令必须在 `driver.stages` 按顺序列出阶段及各阶段的效果；回执用 `failed_stage` 指出停在哪个阶段。

验收：调用前能判断是否修改文档、是否保存原件、是否影响外部目标；复合命令的回执能定位失败的阶段。

### DRV-014 观察不隐含修改

观察阶段不得改变目标内容、保存文档或触发设备动作。必须再生或更新目标才能取得结果的命令，应声明相应的修改效果；连接日志和非目标缓存可以作为已披露的附带效果。

验收：观察前后目标内容与保存状态一致；会改变内容的检查不会被声明成纯观察。

### DRV-015 计划不冒充执行

计划必须说明解析后的目标、参数、依赖、预期动作和未知项，不得修改目标。计划可以报告可检测的前置条件，不能把预计成功写成已经验证成功。

验收：计划输出含基线和未解决的条件，目标保持原状；调用方能区分预计结果与实际观测。

### DRV-016 试执行限定在隔离区

试执行必须使用已验证的隔离副本、模拟后端，或可证明不作用于原目标的执行方式，并返回实际使用的目标。`--dry-run` 产生的试执行产物只能写在工具状态目录下或授权范围内的隔离区，并列在计划的 `outputs` 中；不能隔离时必须拒绝试执行，改用如实声明的预览等级。

验收：试执行可以生成副本产物，原目标及范围外状态保持原状；真实设备动作不能被命名为隔离试执行。

### DRV-017 应用与保存分别记录

应用阶段修改运行中或文件内的目标；保存阶段写入持久存储。直接编辑文件可以同时完成两者。实现必须分别报告变化与持久化，不得因调用成功就推定已保存。

验收：内存修改未保存、成功保存和多文件部分保存有不同的回执；回执给出保存位置及其对应的源状态。

### DRV-018 区分本地产物与对外交付

在授权的输出目录生成产物属于 `artifact` 效果。向共享位置、其他系统或其他接收方交付属于 `deliver` 效果：必须声明目标、源状态和覆盖行为，按交付范围核实，并在回执的 `deliveries[]` 逐项记录结果，`outcome.delivery` 汇总。导出成功不能证明交付成功。

外部拒收时回执为 delivery `rejected`。本次调用生成了本地产物（命令有 `artifact` 效果）时，产物留在 artifacts 中，错误码为 `E_PARTIAL`；只交付已有文件的命令被拒收时没有留下效果，错误码为 `E_NATIVE_FAILURE`。

验收：本地生成和外部交付分别有证据；外部拒收不会被报为已交付，也不会抹掉本次调用已生成的产物。

### DRV-019 声明预览等级

预览必须采用 `plan`（动作计划）、`estimate`（计算或推断的结果）或 `trial_observed`（试执行后读回的结果）之一，并提供基线、未知项和覆盖范围。细分说明放入 `extensions`，不得新增或重新解释核心枚举，也不得把试执行结果无条件保证为最终结果。

验收：只解析参数的预览不标为 trial_observed；随机、动态依赖和外部状态造成的差异有明确说明。

### DRV-020 绑定预览上下文

确认令牌必须绑定目标、动作、参数、依赖、基线修订、授权范围和过期时间（COR-012）。令牌只证明这些上下文曾被本机校验，本身不能扩展授权。

验收：改变参数、目标或已绑定的依赖后，旧令牌不能直接执行；令牌本身不能扩展授权范围。

### DRV-021 检查状态漂移

执行前必须重查命令依赖的可观测基线。发现漂移必须停止，报 `E_CONFLICT`（`state_drift`）并要求重新计划；如果应用接口不能原子地校验并写入，必须披露检查与写入之间的竞争窗口。

验收：界面或另一进程改动了相关目标后，旧计划不会无提示地执行；无法检测的状态明确标为未覆盖。

## 批量、依赖与恢复

### DRV-022 区分独立批量和依赖工作流

独立批量使用基线的批量契约：复数参数、一次 dry-run 汇总整批、一个确认令牌覆盖整批、`--continue-on-error`、`items[]` 与 `summary`，危险批量带 `--dangerous`。
批量的 dry-run 返回一份计划（COR-011）：`total`、按输入顺序去重的 `targets`，以及每个目标的计划项，各带基线快照、预计变化和将使用的 `operation_id`；令牌绑定整个已解析的目标集合，增减任一目标都使令牌失效。
依赖工作流必须表达步骤标识、前置步骤、失败策略和最终目标，不得以默认继续执行代替依赖判断。

验收：独立文件可以分别成功或失败；依赖上一步新建对象的步骤，不会在该对象创建失败后继续运行。

### DRV-023 保留每项真实结果

独立批量必须返回每项状态及其回执或 operation_id，以及汇总计数；部分失败必须在汇总中可见。`summary.total`、`succeeded`、`failed` 只计已尝试的项（基线 §15.5）；未尝试的项标 `skipped_reason`，计入 `summary.skipped`。结果未知的项计入 failed，错误码为 `E_OUTCOME_UNKNOWN`，并在 `summary.unknown` 中单独计数。顶层 `ok: true` 不能被解释为所有项成功。

验收：一项失败时，成功项的证据仍然可以取得；汇总数量与逐项结果一致，未执行的项有原因。

### DRV-024 按依赖决定后续步骤

工作流步骤只有在所需前置条件满足时才能运行。步骤失败、验证未达要求或状态未知时，依赖它的步骤必须停止；没有依赖关系的步骤能否继续，由预先声明的失败策略（`stop` 或 `continue_independent`）决定。

验收：失败不会触发依赖产物的后续交付；跳过、停止和未开始分别说明原因。

### DRV-025 提供可解释的检查点

检查点必须记录捕获的目标、版本、依赖、存储位置、恢复方式和未覆盖的状态。实现可以只提供文件备份或部分恢复，但不得把备份等同于完整的应用事务。

验收：能列出检查点保护的对象；未保存的内存状态、外部效果或设备状态是否包含在内，都有明确答案。

### DRV-026 依据观察报告恢复

恢复操作必须核实当前目标的身份和范围，执行后读回受保护的状态。只有声明的恢复范围全部与检查点一致时，才能把 `change` 报为 `rolled_back`；证据不足时必须报告部分恢复或未知。

验收：撤销接口返回成功但读回仍不一致时，不能报告已回滚；恢复不会覆盖范围外的新修改。

### DRV-027 不推定原子性和幂等性

多步应用、批量保存及撤销不得默认视为原子事务。确认令牌单次消费（基线 §9）；幂等键必须声明作用范围、保留期限和后端保障，并绑定命令、目标及操作内容。同一键对应不同内容必须拒绝为 `E_CONFLICT`（`idempotency_mismatch`）；同一键同一内容返回原回执并标 `replayed: true`，不再派发。记录过期或不可用不能证明原操作未执行，也不能据此盲目重放。同一参数或请求标识不足以证明物理动作或非幂等操作不会重复。

验收：中途失败时如实报告已应用的步骤；同键不同内容不触发第二次原生操作；重放可与新执行区分；过期记录不会被当作未执行。

## 读回、验证与产物

### DRV-028 读回实际目标

修改后必须通过实际应用、设备或独立的文件消费者读取实际状态，或明确声明不可读取的部分。读回应包括目标身份、观测时间、修改的字段及可检测的附带效果。实现必须区分写入器自检与独立读回；回显输入参数或写入器自检不能冒充独立读回。

验收：后端忽略参数或调整数值时，回执呈现实际值；只运行了写入器自检时，检查范围和独立读回的缺口可见，验证状态不超出证据。

### DRV-029 分开执行与领域验证

执行、变化、持久化、交付和验证必须分别报告，遵循核心协议的 `receipt.outcome`。`verification.status` 为 `passed` 只表示声明的检查通过；调用完成和产物存在都不能单独证明领域正确。

验收：操作完成但领域检查失败时，回执同时为 `execution=completed` 和 `verification.status=failed`，错误码为 `E_VERIFY_FAILED`。

### DRV-030 为结论提供检查覆盖

回执必须列出验证对象、源状态、检查方法、适用范围、观测和遗漏。未运行、未完成或不适用的检查必须使用相应的状态；覆盖不足时不得宣称整体正确。

验收：检查一个对象不能代表全部文档；无法启动检查器与检查出错误有不同的状态和证据。

### DRV-031 核实持久化结果

声明保存成功时，必须读取已保存的位置或取得可信的保存证据，并核对所保存的源状态。应用还有未保存的内容时必须披露；只收到保存请求或只写入了部分文件，不能报告全部保存成功。

验收：写入失败、保存到其他位置和多文件部分保存都能分辨；磁盘结果与声称保存的版本对应。

### DRV-032 关联产物与源状态

导出产物必须记录来源文档或文件、基线、依赖、生成选项和产物校验值。同一交付包要求一致的源状态时，必须核实这一约束；无法保证时必须报告不一致或覆盖限制。

验收：中途修改源文档不会产生被标为同一版本的混合交付包；遗漏的产物在清单中可见。

## 会话调度与长任务

### DRV-033 遵守应用调度约束

适配器必须声明操作是否要求应用主线程、特定会话线程或串行执行，并据此调度。应用的要求不能被后台线程、重入或多个 CLI 进程绕过。主线程不可用、尚未派发时返回 `E_BUSY`；已经排队的长任务返回操作状态。

验收：并发请求仍按声明的约束执行；主线程不可用时返回忙碌或任务状态，不进行不受支持的直接调用。

### DRV-034 声明并发保护范围

修改必须在实例、文档或目标所需的范围内防止冲突，声明锁、队列或拒绝策略及其边界。使用锁或租约时必须声明所有者、释放和失效条件；锁失效、CLI 退出或连接断开不证明原生执行已停止。接管前必须核对活动操作及目标状态，无法排除仍在执行时不得启动冲突的写入（`E_CONFLICT`，`lock_held` 或 `unresolved_operation`）。内部锁不能保证界面用户或其他工具不修改目标，仍须结合状态漂移检查。

验收：两个冲突的写入不会交错破坏目标；原生操作仍在运行时，清理陈旧的锁不会直接放行新写入；外部编辑可检测时被识别，不能检测时有覆盖说明。

### DRV-035 使长任务可查询

长任务在 dry-run 时就有 `operation_id`，confirm 返回 `data.operation_status`，之后通过 `operation show` 查询；这些查询只读取记录或观测已有任务，不得重新提交任务。状态名沿用基线 §16.2（`pending`、`running`、`succeeded`、`failed`、`cancelled`），驱动层只增加 `planned`、`cancel_requested`、`partial`、`unknown`。
实现必须在 `driver_profile.record` 声明记录存放在哪里（`store`）、保留多少天（`retain_days`），以及 CLI 退出、重连、实例重启后能否继续查询（`survives_cli_exit`、`survives_reconnect`、`survives_instance_restart`）和其他限制；`operation_status.record` 报告单条记录的可用性和保留期限。记录不可用不能当作任务未执行。
执行中的操作必须持有可续期的租约：执行它的 CLI 进程退出或失联后，租约到期，记录改报 unknown，不能一直停在 running 而永久阻止同一目标的写入（DRV-041）。已提交的长任务同样持有租约，每次成功观测到它仍在 pending 或 running 时续期；没人能观测时到期改报 unknown，之后的观测仍可把它更新为实际状态。

调用方的等待期限与原生执行期限必须分别声明；等待到期不等于取消。进度只能使用后端观测值或标为估计，不能伪造百分比。模态对话框或外部前置条件阻塞时，必须非阻塞地返回：同步调用报 `E_HUMAN_REQUIRED`（COR-024），长任务在 `operation_status.blocked` 中给出 action、原因和续跑入口；不得自动确认含义未知的对话框。

验收：首次响应丢失后仍能按调用方已知的标识查询，或如实报告记录不可用；查询不重提任务；等待超时与原生停止分别报告；模态阻塞不会让 CLI 无限等待或擅自确认。

### DRV-036 区分取消请求与停止结果

取消能力必须声明可以取消的阶段及是否产生恢复动作。接受取消请求不等于已停止，也不等于已回滚；停止后必须重新观测修改与保存状态，观测到停止才报 `cancelled`。

验收：无法中断的阶段明确返回取消未生效；已修改后停止的任务不报告 `change=not_applied`。

### DRV-037 如实处理超时与断连

等待超时或连接中断只能说明调用方没有取得结果。任务可能继续时，必须报告已知的阶段及未知的字段，并提供查询或重连方法；不得把超时自动转换成未修改，也不得用可重试的 `E_TIMEOUT` 报告已派发的修改。

验收：后端超时后实际完成的任务可以被重新识别；取得证据之前，不会自动重复创建对象或发送设备动作。

### DRV-038 收敛未知状态后再依赖执行

结果未知时，必须优先查询任务、读回目标或比较基线。不能确定前置条件时，依赖它的步骤不得继续；允许的恢复动作必须有独立的范围、实际结果和回执。

验收：未知的创建结果不会直接引发同名对象重建；不能收敛时保留未知状态及所需信息，不编造失败结论。

## 设备附加条件

### DRV-039 声明物理效果与观测边界

驱动设备时必须声明动作是否产生物理效果、效果范围、可观测的状态及前置条件。产生物理效果的命令必须标 `dangerous: true`，工具风险档为 T2；只有任务范围显式列出 `physical` 且 `dangerous` 为 true 时才能执行，两次调用都带 `--dangerous`。遥测必须含观测时间；过期或缺失的状态不能充当前置条件满足的证据。

验收：设备状态变化能与命令参数和观测时间关联；前置条件不满足或范围未列出 physical 时，动作在开始前被拒绝。

### DRV-040 不伪造模拟与物理恢复

设备模拟必须标明模拟后端及未模拟的效果。真实物理动作必须走已授权的应用阶段；文件备份、软件撤销或反向命令不能自动证明物理状态已恢复。

验收：模拟结果不会被呈现为真实测量；恢复结论只覆盖重新观测并核实过的物理状态，未覆盖的部分保持未知。

## 未决操作与授权边界

### DRV-041 登记未决操作后再写

结果为 unknown 的操作，以及仍在运行的操作，会阻止同一目标上的新 dry-run 和 confirm：前者返回 `E_CONFLICT`（`unresolved_operation`），后者返回 `E_CONFLICT`（`lock_held`），`details.active_operation` 都给出该操作。仍在运行的，调用方用 `operation show` 等它结束；结果未知的，调用方先查询、独立读回目标，再用 `operation resolve` 登记读回结果（applied、not_applied 或 partial）及依据，之后才能继续写。登记只改变操作记录，不改变目标，也不改写原回执；它需要覆盖原操作效果的任务范围。仍在运行的操作在租约到期前不能登记（DRV-035），晚到的回执单独保存，不覆盖登记结果。

验收：回复丢失后，同一目标的下一次写入在派发前被拒绝；登记之后可以继续；原回执仍保持 unknown，登记单独记录。

### DRV-042 说明授权防护的对象

实现和 Skill 必须如实说明任务范围防护的对象：它阻止外部内容扩大授权、Agent 越出任务、以及选错目标或路径造成的修改。Agent 与用户使用同一个系统账户时，范围文件、令牌密钥和操作记录都在 Agent 可写的位置，这套机制不能防止 Agent 蓄意伪造授权。需要不可伪造的人工批准时，必须使用 Agent 无法写入的身份或带外渠道，并在 reference 和 SECURITY 文档中声明。

验收：文档和 Skill 不把范围文件或确认令牌描述为人工批准的证明；声称防伪造的实现能指出 Agent 无法写入的那一环。

## 验收与开放问题

符合本规范的实现必须按[验证规范](VERIFICATION-SPEC.md)提供条款映射、适用能力及真实执行证据。未支持的能力可以标为不适用并给出能力声明；实际声明支持的能力不能以不适用绕过验收。

至少按实现模式覆盖适用的场景：目标选择、内存与磁盘分离、授权范围内连续执行、缺少授权、越界拒绝、状态漂移、依赖失败、恢复不完整、取消、断连、结果未知与登记、模态阻塞。设备场景另外覆盖模拟与真实动作的区分；不具备的文档、会话或磁盘维度需说明不适用的原因。

以下问题尚未形成统一的字段约定，不影响上述行为义务：

- 应用无法提供稳定的文档版本时，跨适配器的基线和指纹如何互通？
- 原软件在保存时隐式更新其他文档，如何统一描述关联的保存范围？
- 范围文件中的目标选择器目前只到引擎、实例、对象和定位前缀，更细的对象选择由领域扩展定义。
