# 应用与设备操作规范

版本：0.1.0-draft；状态：草案。

本文供 CLI 实现者、适配器作者和验收人员使用，假设读者了解命令行、JSON 和所驱动工具的基本操作。机器接口遵循[核心协议](CORE-SPEC.md)，验证证据遵循[验证规范](VERIFICATION-SPEC.md)。

## 目标与适用范围

本规范定义直接驱动应用或设备时，如何识别目标、控制修改范围、核实结果和处理失败。文件编辑、会话内操作和设备动作均可声明为能力；实现只需支持其公开声明的能力。

本规范不替代应用自身的领域规则、设备操作规程或行业认证。接口合规不能证明设计正确，也不能证明设备适合某项任务。

术语约定：

| 术语 | 含义 |
|---|---|
| 实例 | 一个可识别的应用进程、服务端执行器或设备连接目标 |
| 会话 | 实例中的连接上下文，具有生命周期和连接身份 |
| 文档 | 应用内打开的工程、模型或其他可编辑对象集合 |
| 目标 | 命令实际观察或修改的实例、文档、文件、对象或设备状态 |
| 基线 | 一组已观测的目标状态及其观测时间、版本或指纹 |
| 任务范围 | 调用方已授权的目标、动作、输出位置和限制 |
| 检查点 | 为恢复或比较保存的一组状态与依赖，恢复范围必须明确 |

典型场景包括：在已打开文档中连续修改、在副本中试构建、批处理独立文件、执行有依赖的多步操作，以及查询或驱动设备。

## 能力与目标身份

### DRV-001 声明真实能力

实现必须公开支持的操作阶段、连接方式、工具版本范围、并发限制和恢复能力。原子事务、幂等、撤销、试执行和设备模拟必须分别声明，不得由通用包装器推定。

验收：对未支持能力的调用返回明确错误，且不触发替代操作；能力声明可与实际行为逐项核对。

### DRV-002 明确选定实例

修改命令必须明确实例或唯一解析出的目标。存在多个候选实例时必须要求显式选择，不得依赖窗口焦点或最近使用顺序。新建或连接实例后必须返回其身份。

验收：同时打开两个候选实例，省略选择不能修改任何一个；显式选择只作用于指定实例。

### DRV-003 处理身份生命周期

会话、文档及对象身份必须声明有效期或稳定性；运行实例模式还必须识别连接代际。重连后必须核对实例、文档和活动操作，不能因名称相同而沿用旧代际引用。重连、关闭再打开、再生或替换对象后，失效身份必须拒绝使用或重新解析，并返回解析依据。

验收：重启实例、重连或重建对象后，旧身份不会误指向另一个对象；新的连接不会静默接管旧代际操作。

### DRV-004 绑定文档和文件

具有文档或文件状态的模式必须区分文档身份与文件路径，记录文档是否新建、是否有保存位置。路径必须解析为明确位置；两个文档指向同一路径时，修改与保存不得静默选取其中一个。设备等无文档或文件的模式必须标明这些维度不适用，并解释原因。

验收：按模式覆盖未保存文档、同名异路径文件和同路径多会话；无文档或文件的模式报告不适用，不伪造目标。

### DRV-005 分别观测内存和磁盘

具有会话状态或磁盘状态的模式必须分别报告适用维度，包括未保存修改、观测时间及版本或指纹。存在但无法读取的状态必须标为未知，不能用磁盘指纹代表内存版本。文件模式没有运行中会话、设备模式没有文件持久化等情形必须标明不适用，并解释原因；持久化维度遵循核心协议的 `not_applicable` 状态。

验收：按模式验证内存修改与磁盘基线分离；不存在的状态维度报告不适用，存在但不可观测的部分报告未知。

### DRV-006 声明单位与坐标

具有量纲或空间含义的参数必须声明适用的单位；坐标系、原点和容差按参数语义声明。计数、标识符及索引不要求单位。默认值必须可发现；输入与应用单位不同必须显式转换并记录，禁止猜测缺失单位。

验收：相同物理量用不同支持单位输入，读回结果在声明容差内相等；不支持的单位不会静默降级。

### DRV-007 记录影响结果的依赖

执行前必须识别命令所需的库、模板、参考对象、插件和配置，并记录可取得的版本或指纹。缺失依赖必须在可检测的最早阶段返回；无法固定的依赖必须披露。

验收：替换已识别依赖后，结果证据能区分两次环境；缺失库不会生成伪成功结果。

### DRV-008 显式管理实例生命周期

启动、连接、打开、关闭和重启必须声明其作用范围。运行实例模式必须区分由工具启动并管理的实例（`owned`）与附着已有实例（`attached`）；所有权标记不能扩展任务授权。CLI 退出、分离连接（detach）和关闭原应用必须分别声明策略，附着实例不得因退出或分离而隐式关闭。关闭或重启可能丢弃未保存修改时，必须检查任务授权并报告该影响，不得把它隐藏在普通查询中。

验收：查询失败不会擅自重启实例；退出附着会话保留原应用和已有修改，生命周期操作能说明哪些文档受影响及修改是否保存。

## 任务范围与工作区

### DRV-009 记录任务授权

修改前必须取得可引用的任务范围，至少覆盖目标、允许动作和输出位置。范围可以来自已授权任务、调用方上下文或显式参数，不要求每个命令重新人工确认。

验收：同一授权范围内的连续修改可自主执行；回执可关联其授权来源，不把确认令牌当成人类批准证明。

### DRV-010 在越界前停止

动作超出任务范围，或要求丢弃未授权的已有工作、改写共享目标、改变全局配置或向范围外交付时，必须在该动作开始前停止并说明缺少的授权。不得重复索取已存在的授权。

验收：在允许修改的副本中正常迭代；试图覆盖范围外文件时，目标保持原状且错误指出具体边界。

### DRV-011 明确隔离边界

工作区必须列出可写目标、输出目录和共享依赖。声称隔离时，必须说明隔离方法及未覆盖的副作用。目录副本不能证明应用配置、共享库或外部系统同样隔离。

验收：试执行后的写入可与声明范围核对；共享依赖的写入被禁止或单独授权并如实记录。

### DRV-012 保留基线与已有工作

接手已有文档时，必须在首次修改前观测目标和未保存状态，并按恢复能力建立基线。不能建立完整基线时，必须声明可恢复范围，不得承诺保留全部状态。

验收：已有修改不会被新基线静默丢弃；恢复说明区分磁盘文件、内存文档及未捕获状态。

## 操作阶段与预览

### DRV-013 区分操作阶段

命令必须声明属于观察、计划、试执行、应用、保存或对外交付中的哪些阶段。一个命令可包含多阶段，但必须逐项声明顺序、作用目标及各阶段产生的效果。

验收：调用前可判断是否修改文档、是否保存原件及是否影响外部目标；复合命令回执可定位失败阶段。

### DRV-014 观察不隐含修改

观察阶段不得改变目标内容、保存文档或触发设备动作。必须再生或更新目标才能取得结果的命令，应声明相应修改阶段；连接日志和非目标缓存可作为已披露的附带效果。

验收：观察前后目标内容与保存状态保持一致；会改变内容的检查不会被声明成纯观察。

### DRV-015 计划不冒充执行

计划阶段必须说明解析后的目标、参数、依赖、预期动作和未知项，不得修改目标。计划可报告可检测的前置条件，不能把预计成功写成已经验证成功。

验收：计划输出含基线及未解决条件，目标保持原状；调用方可区分预计结果与实际观测。

### DRV-016 试执行限定在声明范围

试执行必须使用已验证的隔离副本、模拟后端或可证明不作用于原目标的执行方式，并返回实际使用的目标。若不能隔离，必须拒绝试执行或要求改用如实声明的应用阶段。

验收：试执行可生成副本产物，原目标及范围外状态保持原状；真实设备动作不能被命名为隔离试执行。

### DRV-017 应用与保存分别记录

应用阶段修改运行中或文件内的目标；保存阶段写入持久存储。直接编辑文件可同时完成两者。实现必须分别报告修改与持久化状态，不得因调用成功自动推定已保存。

验收：内存修改未保存、成功保存和多文件部分保存有不同回执；返回保存位置及所对应的源状态。

### DRV-018 区分本地产物与对外交付

在授权工作区生成产物属于该工作区内的操作。向共享位置、其他系统或其他接收方交付必须声明目标、源状态和覆盖行为，并检查交付范围；导出成功不能证明交付成功。

验收：本地生成和外部交付分别有证据；外部拒绝接收时，本地产物不会被报告为已交付。

### DRV-019 声明预览等级

预览必须采用 `plan`（动作计划）、`estimate`（计算或推断的结果）或 `trial_observed`（试执行读回结果）之一，并提供基线、未知项和覆盖范围。细分说明必须放入 `extensions`，不得新增或重新解释核心枚举，也不得将试执行结果无条件保证为最终结果。

验收：仅解析参数的预览不标为试执行读回；随机、动态依赖和外部状态造成的差异有明确说明。

### DRV-020 绑定预览上下文

应用若引用预览或确认令牌，必须验证目标、动作、参数、依赖及有效期仍匹配。令牌只能证明这些上下文曾被校验；只有关联有效授权来源时才能作为任务范围的引用。

验收：改变参数、目标或已绑定依赖后，旧预览不能直接应用；令牌本身不能扩展授权范围。

### DRV-021 检查状态漂移

应用前必须重查命令依赖的可观测基线。发现漂移必须停止或重新计划；若应用接口不能原子地校验并写入，必须披露检查与写入之间的竞争窗口。

验收：界面或另一进程改动相关目标后，旧计划不会无提示执行；无法检测的状态明确标为未覆盖。

## 批量、依赖与恢复

### DRV-022 区分独立批量和依赖工作流

批量入口必须声明各项是否独立。依赖工作流必须表达步骤标识、前置步骤、失败策略和最终目标，不得以默认继续执行替代依赖判断。

验收：独立文件可分别成功或失败；依赖上一步新建对象的步骤不会在该对象创建失败后继续运行。

### DRV-023 保留每项真实结果

独立批量必须返回每项状态、回执和汇总计数，并声明遇错继续或停止。部分失败必须在汇总中可见；顶层受理成功不能被解释为所有项成功。

验收：一项失败时，成功项证据仍可取得；汇总数量与每项结果一致，未执行项有原因。

### DRV-024 按依赖决定后续步骤

工作流步骤只有在所需前置条件满足时才能运行。步骤失败、验证未达要求或状态未知时，依赖步骤必须停止；无依赖步骤能否继续由预先声明的策略决定。

验收：失败不会触发依赖产物的后续交付；跳过、停止与未开始能够分别说明原因。

### DRV-025 提供可解释的检查点

检查点必须记录捕获目标、版本、依赖、存储位置、恢复方式及未覆盖状态。实现可以只提供文件备份或部分恢复，但不得把备份等同于完整应用事务。

验收：能列出检查点保护的对象；未保存内存状态、外部效果或设备状态是否包含均有明确答案。

### DRV-026 依据观察报告恢复

恢复操作必须检查当前目标身份和范围，执行后读回受保护状态。只有声明恢复范围全部与检查点一致时，才能将 `change` 报为 `rolled_back`；证据不足必须报告部分恢复或未知。

验收：撤销接口返回成功但读回仍不一致时，不能报告已回滚；恢复不会覆盖范围外的新修改。

### DRV-027 不推定原子性和幂等性

多步应用、批量保存及撤销不得默认视为原子事务。重试去重必须声明键的作用范围、记录保留期限和后端保障，并绑定命令、目标及操作内容。同一键对应不同内容必须拒绝为冲突；记录过期或不可用不能证明原操作未执行，也不能据此盲目重放。同一参数或请求标识不足以证明物理动作或非幂等操作不会重复。

验收：中途失败如实报告已应用步骤；同键不同内容不触发第二次原生操作，过期记录不会被当作未执行，未声明可重试的操作不自动重放。

## 读回、验证与产物

### DRV-028 读回实际目标

修改后必须通过实际应用、设备或独立文件消费者读取实际状态，或明确声明不可读取的部分。读回应包括目标身份、观测时间、修改字段及可检测附带效果。实现必须区分写入器自检与独立读回；回显输入参数或写入器自检不能冒充独立读回。

验收：后端忽略参数或调整数值时，回执呈现实际值；仅运行写入器自检时，检查范围和独立读回缺口可见，验证状态不超出证据。

### DRV-029 分开执行与领域验证

执行、修改、持久化及验证必须分别报告，遵循核心协议的 `receipt.outcome`。`verification.status` 为 `passed` 只表示声明的检查通过；调用完成和产物存在均不能单独证明领域正确。

验收：操作完成但领域检查失败可同时表现为 `execution=completed` 和 `verification.status=failed`。

### DRV-030 为结论提供检查覆盖

回执必须列出验证对象、源状态、检查方法、适用范围、观测和遗漏。未运行、未完成或不适用的检查必须使用相应状态；覆盖不足不得宣称整体正确。

验收：检查一个对象不能代表全部文档；无法启动检查器与检查出错误有不同状态和证据。

### DRV-031 核实持久化结果

声明保存成功时，必须读取已保存位置或取得可信保存证据，并核对所保存的源状态。应用尚有未保存内容时必须披露；仅收到保存请求或写入部分文件不能报告全部保存成功。

验收：写入失败、保存到其他位置和多文件部分保存均可辨别；磁盘结果与声称保存的版本对应。

### DRV-032 关联产物与源状态

导出产物必须记录来源文档或文件、基线、依赖、生成选项和产物校验值。同一交付包要求一致源状态时，必须核实该约束；无法保证时必须报告不一致或覆盖限制。

验收：中途修改源文档不会产生被标为同一版本的混合交付包；遗漏产物在清单中可见。

## 会话调度与长任务

### DRV-033 遵守应用调度约束

适配器必须声明操作是否要求应用主线程、特定会话线程或串行执行，并据此调度。应用要求不能被后台线程、重入或多个 CLI 进程绕过。

验收：并发请求仍按已声明约束执行；主线程不可用时返回忙碌或任务状态，不进行不支持的直接调用。

### DRV-034 声明并发保护范围

修改必须在实例、文档或目标所需范围内防止冲突，声明锁、队列或拒绝策略及其边界。使用锁或租约时必须声明所有者、释放和失效条件；锁失效、CLI 退出或连接断开不证明原生执行已停止。接管前必须核对活动操作及目标状态，无法排除仍在执行时不得启动冲突写入。内部锁不能保证界面用户或其他工具不修改目标，仍须结合状态漂移检查。

验收：两个冲突写入不会交错破坏目标；原生操作仍运行时，陈旧锁清理不会直接放行新写入；外部编辑可检测时被识别，不能检测时有覆盖说明。

### DRV-035 使长任务可查询

首次分发长任务前，调用方必须已知 `operation_id`，或已知可查询映射到该操作的 `request_id`；任务记录必须保留该关联。长任务必须提供目标、阶段、开始时间和状态、结果查询入口；这些查询只能读取记录或观测已有任务，不得重新提交任务。实现必须声明记录保留期限、过期行为及 CLI 退出、重连或实例重启后的查询限制；记录不可用不能当作任务未执行。

调用方等待期限与原生执行期限必须分别声明；等待到期不等于取消。进度只能使用后端观测或标为估计，不能伪造百分比。模态对话框或外部前置条件阻塞时，必须非阻塞地返回原因、已知操作状态及明确恢复方向；不得自动确认含义未知的对话框。

验收：首次响应丢失后仍能按调用方已知标识查询，或如实报告记录不可用；查询不重提任务。等待超时与原生停止分别报告，模态阻塞不会导致 CLI 无限等待或擅自确认。

### DRV-036 区分取消请求与停止结果

取消能力必须声明可取消阶段及是否产生恢复动作。接受取消请求不等于已停止，也不等于已回滚；停止后必须重新观测修改与保存状态。

验收：无法中断阶段明确返回取消未生效；已修改后停止的任务不报告 `change=not_applied`。

### DRV-037 如实处理超时与断连

等待超时或连接中断仅能说明调用方没有取得结果。任务可能继续时，必须报告已知阶段及未知字段，并提供查询或重连方法；不得把超时自动转换成未修改。

验收：后端超时后实际完成的任务可被重新识别；未取得证据前不自动重复创建对象或发送设备动作。

### DRV-038 收敛未知状态后再依赖执行

结果未知时，必须优先查询任务、读回目标或比较基线。不能确定前置条件的依赖步骤不得继续；允许的恢复动作必须有独立范围、实际结果和回执。

验收：未知创建结果不会直接重建同名对象；不能收敛时保留未知状态及所需信息，不编造失败结论。

## 设备附加条件

### DRV-039 声明物理效果与观测边界

驱动设备时必须声明动作是否产生物理效果、效果范围、可观测状态及前置条件。遥测必须含观测时间；过期或缺失状态不能充当满足前置条件的证据。

验收：设备状态变化可与命令参数和观测时间关联；前置条件不满足时，动作在开始前被拒绝。

### DRV-040 不伪造模拟与物理恢复

设备模拟必须标识模拟后端及未模拟效果。真实物理动作必须走已授权的应用阶段；文件备份、软件撤销或反向命令不能自动证明物理状态恢复。

验收：模拟结果不会被呈现为真实测量；恢复结论仅覆盖重新观测并核实的物理状态，未覆盖部分保持未知。

## 验收与开放问题

符合本规范的实现必须按[验证规范](VERIFICATION-SPEC.md)提供条款映射、适用能力及真实执行证据。未支持能力可标为不适用，并给出能力声明；实际声明支持的能力不能以不适用绕过验收。

至少按实现模式覆盖适用场景：目标选择、内存与磁盘分离、授权范围内连续执行、越界拒绝、状态漂移、依赖失败、恢复不完整、取消、断连与结果未知。设备场景另外覆盖模拟与真实动作的区分；不具有的文档、会话或磁盘维度需说明不适用原因。

以下问题尚未形成统一字段约定，不影响上述行为义务：

- 应用无法提供稳定文档版本时，跨适配器基线和指纹如何互通？
- 原软件在保存时隐式更新其他文档，如何统一描述关联保存范围？
- 长任务跨实例重启继续运行时，任务身份与证据保留期限是否需要公共配置？
- 是否需要可选的公共任务 Schema，以统一状态、结果、取消和阻塞信息？当前实现必须公开自己的可查询契约，不要求支持统一任务执行器。
