# 能力验收与规范毕业

规范版本：`1.0.1`；驱动结构版本：`2.0`；基线：ai-native-cli-spec `v1.6.3`。

目标是让 Agent 在授权范围内完成可独立核实的真实任务。命令数量、JSON 返回成功和静态合同通过，都不能代替实际结果。这里把仓库已有 VER-024、DEL-025 的规范准入整理成可执行入口，再按 file/session/device 与实际能力给出任务选择建议；工程、内容处理、服务和设备均按同一公共机制取证。

规范性要求来自正文的编号条款。下面的任务是验收建议，不要求所有工具实现每个模式、格式或任务；具体支持范围仍由 reference 声明，并按相应条款验证。历史品牌任务在[非规范性工程案例附录](ENGINEERING-CASE-STUDIES.md)，不作为规范毕业门槛或支持清单。

## 规范怎样毕业

规范的最小准入沿用 VER-024：正文、基线和机器合同一致；正反例与有意义的边界回归通过；本次交付 ZIP 具备完整必需文件且重新消费成功；至少一种真实文件产物经过独立消费者。SDK 和种子工程必须能实例化、运行自描述与协议测试；未实现原生命令明确拒绝。一个经过独立消费的文件能力可以满足这项规范门禁；每个具体工具、运行实例、物理设备和未来命令另行验收。

本地运行（Python、浏览器和可选审计工具已具备时）：

```powershell
python scripts/check_graduation.py --audit --browser "C:/Program Files/Google/Chrome/Application/chrome.exe" --output D:/work/spec-acceptance-new
```

输出 `acceptance.json`、实际 stdout/stderr、依赖审计 JSON 和消费者产物。`--audit` 使用已有 pip-audit，不解析/安装依赖或修复环境；不带该选项仍可执行离线回归与消费，但不能取得 release_ready。它记录当前提交、未提交状态及全部规范/实现/测试文件哈希，区分 `local_passed` 与 `release_ready`；缺少交付包时后者为 false。FIFO、符号链接等平台跳过项保留在测试日志，不能写成已测。

冻结到获授权的干净提交后，用既有构建器生成规范 ZIP；取得独立预期校验值，再执行：

```powershell
python scripts/check_graduation.py --audit --browser "C:/Program Files/Google/Chrome/Application/chrome.exe" --output D:/work/spec-package-acceptance-new --bundle dist/tool-driver-cli-spec-1.0.1.zip --expected-sha256 <trusted-sha256>
```

该入口拒绝覆盖证据目录，重新校验和解包 ZIP，在包目录运行静态检查、全套测试和真实浏览器消费，而非只检查开发目录。`release_ready` 还要求包字节与干净源码逐项一致、提交相同、STATUS 为 stable；它表示本地发布材料具备条件，不证明发布者身份、GitHub 实际资产或 SkillHub 安装。

本次规范版本为 1.0.1，驱动结构为 2.0，与已有 Release 1.0.0 的结构 1.0 不兼容；调用方必须同时固定规范版本、结构标识、来源和文件哈希，按[实施与迁移指南](ADOPTION-GUIDE.md#从已发布的驱动结构-10-迁移)升级。已有标签和资产保持原样，本次发布使用新标签 `v1.0.1`。结构版本独立于规范版本，两套不同字节分别绑定各自的发布包。

## 按模式选择最小真实任务

建议每个工具先冻结一条真正有用的任务，明确输入、预期变化、保护不变量、适用环境与独立判定方法，再按能力提高成熟度。每个场景留下：实际目标与适用依赖指纹；适用的单位/坐标及保护对象；原样 argv、退出码和响应；计划与范围；五维回执；实际读回及保存/交付证据；失败与未知路径，以及未覆盖项。不存在的状态按模式说明不适用，无法观测的状态保持未知；缺少应用、许可或证据不是不适用。模拟故障只证明协议恢复，不证明原生服务已经抗故障。

| 模式 | 建议的首条任务 | 对应条款与可复核结果 |
|---|---|---|
| file | 在授权副本修改一个明确属性，保护其余内容，再由独立消费者重新加载 | DRV-004/007/017/028/031、VER-009/010/013/020：实际文件与依赖固定；预期变化和保护不变量均有断言；直接修改同时持久化时如实报告，不虚构未保存内存状态 |
| session | 显式选择运行实例中的对象，修改一个属性，读回；按任务要求保留未保存状态或保存后重新加载 | DRV-002/003/005/008/033/034、VER-004/009/010/013：实例、连接代际、实际加载组件与目标状态分别核实；保存策略、已有工作和调度约束有证据 |
| device | 先完成带身份与时间的真实状态读取；声明物理动作时，再选一项已获授权且有领域安全条件的有限动作并独立观测 | COR-008、DRV-028/039/040、VER-009/018/020：设备、观测时效、单位与前置条件可复核；真实动作具有 physical 授权、T2、危险标记及实际效果证据。查询或模拟通过不能提升物理动作成熟度 |

## 按实际能力补充验收

以下行按命令的实际语义适用，用于把领域事实映射到公共要求，不增加某个领域的必备功能。

| 能力或状态 | 应保留的判定依据 | 关键失败验证与条款 |
|---|---|---|
| 项目或关联输入有依赖 | 参与结果的主输入、配置、规则、库/外部资源及可取得的版本或指纹；无法固定项的局限 | 依赖缺失或替换，旧计划停止；不能用占位依赖冒充任务完成。DRV-007/020/021、VER-004/014 |
| 一次保存或导出产生多个产物 | 全部预期产物、共同源状态、依赖集合、生成选项与逐项校验值；由声明的消费者重新加载 | 漏文件、部分保存、混合源版本或消费时切换依赖不能汇总为通过。DRV-017/031/032、VER-013/016 |
| 领域检查或规则判定 | 实际检查器身份、输入、配置、排除项、覆盖范围、发现与未检查项 | 运行完成和零报告项都不能替代完整领域结论；检查器缺失保持未完成。DRV-029/030、VER-003/011 |
| 多组件或长期运行后端 | 客户端、磁盘组件与实际运行/加载组件分别观测；连接代际与目标身份 | 旧后端仍运行、重连或调度忙碌不冒充新版本已生效。COR-009、DRV-003/033/034、VER-004/021 |
| 有量纲或空间语义 | 实际单位、坐标系、转换策略、容差与读回值；纯文本、ID 和计数不虚构单位 | 不支持单位、过期遥测或错误坐标不得静默接受。COR-010、DRV-006/039、VER-018 |
| 存在未保存状态或结果丢失 | 内存与持久存储各自的观测、已有修改、预知 operation_id、记录与独立读回 | 不授权保存时不持久化；无法分离则派发前拒绝。未知结果先查、读回、登记再继续，不盲目重发。DRV-005/012/017/038/041、VER-013/015/020、SKL-007 |

## 当前参考实现及证据范围

[SVG 标题适配器](../examples/engineering/svg_title_driver.py)是一个非规范性的真实文件模式参考实现，配套[注册表](../examples/engineering/registry.json)和[CLI 边界测试](../tests/test_engineering_example.py)。它读取已有 SVG，计划修改标题，在授权范围内确认保存，保护标题以外的所有字节，并持久化可跨进程查询的操作记录；无范围、文件漂移和非法 XML 都有实际拒绝测试。测试还在独立 Python 进程重开文件并核实标题、几何与尺寸单位。

仓库当前 check_graduation 的真实浏览器消费进一步检验该参考文件的几何、毫米单位、保存重开、失败判定和本地失回复恢复；具体通过结论必须绑定对应源码、包与运行记录。该入口继续保留真实消费门禁，但 SVG 与浏览器是这一参考试验的实现选择，不是每个采用方的格式或运行时要求。这些证据仅覆盖所测文件能力与协议路径，不能外推到其他领域、运行实例或真实设备；新工具仍须接入自己的适配器与独立判定方法。
