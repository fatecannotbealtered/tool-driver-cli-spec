# 实施与迁移指南

规范版本：`1.0.0`。

本文供 CLI 实现者和适配器作者采用规范，假设读者了解 JSON、命令行测试和目标工具的基本操作。
规范版本稳定表示公共契约及规范包通过准入；具体产品按能力、模式和环境保留自己的成熟度。

## 先确定首批范围

从一个可核实的目标和一组完整操作开始，例如观察、修改、读回、保存和重新消费。
在运行实例、文件或设备模式中选择实际采用的模式，记录授权目标、效果、必要依赖和输出位置。
没有的会话、撤销、设备或保存能力应声明不适用，不为凑齐命令目录虚构底层保证。
每项公开行为建立能力 ID、阶段、环境、适用条款和验收记录的对应关系。

## 固定公共契约

1. 从获授权来源取得确定版本的规范包，核实可信来源、包校验值及组件清单。
2. 在项目中记录规范版本、Schema 版本、来源提交、公共文件哈希，以及适用条款。
3. 原样保存公共 Schema 和校验入口，用本地副本完成离线检查；升级不依赖临时拉取分支最新内容。
4. 领域规则单独维护，专有字段放入 `extensions`；不修改公共字段、枚举、错误含义或引用定义。

CLI 产品版本、组件协议、机器 Schema 和规范版本分别管理。
产品使用稳定规范不等于产品能力已实测；应用或组件版本升级后，应重新发现能力并核实兼容范围。
已支持模式、命令、flag 或语义的删除按破坏性变化处理，不能只凭输出 Schema 未变就维持兼容声明。

固定版本检查入口如下，尖括号表示需要替换的实际路径；在取得的规范包根目录调用：

```powershell
python scripts/check_adoption.py --lock "<固定版本记录.json>" --root "<消费项目目录>" --bundle "<已取得的规范ZIP>"
```

锁定记录符合 [固定版本记录 Schema](../schemas/adoption-lock.schema.json)，从实际包的 manifest 取得提交与公共文件哈希。
[结构样例](../examples/valid/adoption-lock.json) 使用合成提交和哈希，仅用于说明字段，不能直接证明一个实际安装。
该入口只读锁定记录、规范 ZIP 和登记的公共副本，核实包哈希、来源提交及原始 Schema 字节。
它拒绝越界、同名冲突、缺失文件和符号链接或 junction，不联网、不更新副本，不以重新下载覆盖漂移。
锁定记录本身必须来自受控来源；校验内容一致不能认证记录作者或包发布者。

## 实现最小闭环

先提供默认 UTF-8 JSON、稳定错误、能力发现和环境检查，再连接实际适配器。
reference 必须给出可离线解析的请求与结果 Schema、参数绑定、阶段、错误引用和带输入的 argv 示例。
对可能修改的操作，在执行前确定目标、基线、授权和预知查询标识，失败后保留实际状态。
应用、修改、保存和验证分别报告，使用公共计划、回执、快照及证据结构。
需要列表、长任务或组合流程时采用相应公共结构，增加领域规则而不重新定义公共语义。

实现完成后用独立读回检查目标，用重新加载或独立消费者检查持久化产物。
首次回复丢失、部分应用、状态漂移、锁失效和取消需按支持范围补充失败路径。
不能取得实际原生结果的能力保持 `draft` 或 `experimental`，说明限制和待检查项。

## 把静态检查与实际调用分开

静态符合性检查处理公共 Schema、reference 引用、参数类型、默认值、枚举、错误表和示例请求。
它不得自动执行示例 argv，也不能证明 CLI 实际接受这些参数、按声明退出或产生真实修改。
命令级测试需实际运行 CLI，保存输入、输出、退出码、环境和测试报告，再关联到能力声明。
模拟适配器用于协议失败路径；真实文件、运行应用和设备的证据分别标记，并绑定实际源状态。
产品发布检查实际下载包与运行组件身份，规范仓库的静态检查不能替代该步骤。

在规范包根目录，可先用自带 reference 样例调用公共校验入口：

```powershell
python scripts/validate_contract.py --schema reference --input examples/valid/reference-experimental.json
```

验收产品时，将 `--input` 替换为实际保存的产品输出或声明文件；`-` 表示从 stdin 读取。
支持 response、reference、receipt、plan、operation-status、workflow、query-page、release-manifest、evidence 和 adoption-lock。
common 只提供共享定义，不作为独立实例契约验收。诊断说明失败约束，不复述输入值。
可用 `--max-bytes` 设置输入上限；检查不联网、不执行 argv 示例，返回 verify 阶段的标准 JSON 信封。
通过时退出码为 `0`，结构或语义不符合为 `2`，输入 I/O 失败为 `1`。输入限制不能用来隐藏不完整内容。

规范仓库自身的一致性与边界测试分别调用：

```powershell
python scripts/check_spec.py
```

```powershell
python -m unittest discover -s tests -v
```

这些入口验证公共规范实现和样例；消费产品还需运行其自己的命令级与真实环境套件。

源码工作树干净且前述检查通过后，构建规范包：

```powershell
python scripts/build_spec_bundle.py
```

构建后校验 ZIP 与校验清单：

```powershell
python scripts/verify_spec_bundle.py --bundle dist/tool-driver-cli-spec-1.0.0.zip --checksum dist/tool-driver-cli-spec-1.0.0.sha256
```

也可用 `--expected-sha256` 提供已取得的期望值。没有独立期望值时，只能报告包内部一致性，不能认证来源。
ZIP 校验不解压到磁盘；默认解压内容上限为 32 MiB，可用 `--max-uncompressed` 明确调整。
包、校验清单和固定记录输入必须是普通文件，不能用隐式管道等待另一个进程提供内容。
最多支持 4096 个目录项、4 MiB 中央目录及 STORED/DEFLATED 压缩；不接受加密、分卷、ZIP64 或链接条目。
哈希不符和结构错误退出码为 `2`，实际输入 I/O 失败为 `1`；结果均使用 verify 阶段的 JSON 信封。

## 最小 Skill 配方

Skill 用任务意图组织操作，不复制整份命令手册。最小内容包括：

- 触发意图和适用边界，例如只在明确选择的对象内修改并交付产物。
- CLI 可执行入口、兼容的产品与协议版本范围，以及必要应用、许可和适配器前提。
- 首次使用和版本变化后的能力发现、环境读回及适用变更检查。
- 观察、计划、范围内执行、读回、保存或导出的最小配方。
- 错误处理：冲突时重新观察，部分应用按逐项结果恢复，未知结果先查询，禁止盲目重发。
- 成熟度限制和证据入口；不在 Skill 中替未验证能力作出可用性承诺。

一份最小任务配方可以这样组织：

```outline
确认目标、输出位置和已授权动作。
读取 reference 与环境检查，核实实际版本和能力范围。
观察目标与必要依赖，取得基线。
按运行时 Schema 准备计划并核实前提。
在授权范围内执行；回复丢失时按预知标识查询。
读回实际变化；按需保存、导出并重新消费产物。
交付来源、实际状态、检查范围和未完成项。
```

具体参数从当前 reference 获取。例子中的对象、路径和授权标识必须替换为本次真实任务的值。
工具或 Skill 版本变化后重新检查兼容组合；发现不兼容时停止依赖该能力的操作。

## 迁移已有项目

先列出公开行为和现有结果，确定哪些已经符合，哪些需要适配，哪些底层能力无法证明。
优先补目标身份、实际状态和未知结果核实，再补公共声明、静态守卫、命令级报告与产物验证。
保留已有业务功能，通过适配层转换公共结构；转换不能把部分成功、未保存或未知结果改写为成功。
逐能力声明迁移进度，不把少量兼容能力合并成全产品通过。
升级公共版本时审阅差异，更新固定版本与哈希，重验受影响的产品能力和 Skill 配方。

## 交付验收

规范包按 [规范发布门禁](DELIVERY-SPEC.md#del-025规范发布门禁) 校验文本、公共契约、边界测试和独立文件消费。
产品包按 [产品发布门禁](DELIVERY-SPEC.md#del-019产品发布门禁) 验证安装、实际组件、声明能力及适用升级与恢复。
GitHub Release 和 SkillHub 使用同一套可追溯产物；上传、绑定、发布和实际安装分别记录结果。
SkillHub 原生多文件包支持仍由实际路径验证，不能从规范稳定状态推定。
