# 机器结构与状态反例

这些示例是人工构造的协议样例，全部使用合成的身份、版本和证据引用。
它们没有连接真实应用或设备，也没有交付示例 manifest 中声明的组件文件。

`index.json` 记录每个样例使用的 Schema 和预期结果，`purpose` 写明它要说明的那条规则。

- `valid/`：dry-run 计划、已应用未保存、仅保存、交付、设备读回的回执；成功、部分、未知、验证失败、交付被拒、缺授权、需要人处理、用法错误、漂移等信封；批量、列表、依赖工作流、操作记录；reference、context、doctor、scope、changelog、证据、manifest 和固定记录。
- `invalid/`：每个反例只违反一条规则，例如在顶层增加 `request_id`、把部分修改报为成功、未知结果可重试、已派发后报可重试的超时、缺少授权详情、写命令缺少 dry-run 示例、改动核心错误码的退出码、内联公共 Schema、只读范围带修改效果等。

示例中的命令和 `argv` 只用于检查声明，校验脚本不会执行它们，也不能证明真实 CLI 的参数解析。

```powershell
python scripts/check_spec.py
```

脚本检查 JSON Schema 及可以静态判断的状态关系（包括由回执推导的错误码），不能证明回执由实际工具产生，也不能证明领域正确性。
