# tool-driver-cli-spec

面向真实应用与设备的 Agent CLI 操作规范。

规范版本：`1.0.0`；状态：`stable`；机器 Schema 版本：`1.0`。

本规范供 CLI 实现者、适配器作者和验收人员使用。读者应了解命令行、JSON，以及所驱动工具的基本操作。

## 目标

让 Agent 能在明确的任务范围内驱动工具，连续观察、修改、检查和迭代，并取得可复核的结果。
每项操作必须能说明目标、实际变化、保存状态、验证范围，以及失败后留下的状态。

适用对象包括运行中的应用实例、应用使用的文件格式和可识别的设备连接。
规范不限定实现语言、操作系统或行业，也不要求所有实现支持全部操作类型。

## 实施顺序

1. 选择驱动模式、目标身份和首批能力，固定规范及 Schema 版本。
2. 先实现 JSON、reference、环境检查和操作记录，再连接原应用或设备适配器。
3. 按能力补齐命令级契约检查、真实读回和产物验收，记录失败路径与未覆盖项。
4. 从版本化包验证安装和实际组件身份，再按成熟度交付。

简单文件工具只实现适用部分；长期会话、设备动作和工作流的附加条件按能力声明验收。

## 设计原则

- 授权按任务范围表达，范围内的连续迭代不要求每一步重新人工确认。
- 计划、估计和隔离试执行分别标明；设备真实动作不能冒充无副作用预览。
- 执行、修改、保存和验证分别报告；成功调用不能代替领域正确性。
- 独立批量与依赖工作流分别处理；恢复能力由实际工具提供，并按实际结果报告。
- 查询、修改和产物必须绑定明确的实例、对象、版本及必要依赖。

## 发布与分发

具体 CLI 产品以 GitHub Release 形成版本化产物，再将同一套产物交给 SkillHub 分发。
不发布到 npm registry，目标机器安装也不默认依赖 npm。

CLI、适配器、插件和 Skill 必须声明配套版本。原应用安装、许可、注册和重启有单独的作用范围。
SkillHub 的多文件原生包与安装方式仍需实测；未验证的格式不能写成已支持。

本仓库的规范包包含文档、Schema、示例、符合性入口及测试，不作为具体 CLI 产品登记。

## 本地校验

校验脚本需要 Python 3.11+。依赖只用于规范仓库的校验，不要求每个 CLI 使用 Python。

```powershell
python -m pip install -r requirements-dev.txt
python scripts/check_spec.py
python -m unittest discover -s tests -v
python scripts/build_spec_bundle.py
```

安装依赖后，检查结构、正反例、状态约束、条款编号和本地链接，再运行实际命令边界与交付测试。
构建命令只在工作树干净时，从该提交的文件生成规范 ZIP、manifest 和校验清单。
产物写入 `dist/`，不会发布 Release 或上传 SkillHub。

产品输出可通过 `scripts/validate_contract.py` 离线检查；固定规范副本和 ZIP 使用相应交付校验入口，见实施与迁移指南。
结构及命令边界测试不构成真实应用或设备证据；独立文件消费探针单独执行并记录实际环境与范围。

## 适用边界

身份映射、领域判定器、来源证明方式和分发平台的原生包支持，需在声明的环境中继续验证。
具体实现可增加领域规则，但必须说明适用条件、检查范围和未覆盖项，不得扩大既有授权。
